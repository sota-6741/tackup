# Screens

画面ごとの仕様。要件は [requirements.md](requirements.md) を正とし、ここでは「何を表示し、何ができ、どの状態をどう見せるか」を決める。

## 共通ルール

### 部品の置き場所

| 層 | 場所 | 中身 |
| -- | -- | -- |
| 汎用の部品 | `src/shared/presentation/components/ui/` | shadcn/ui（Base UI）が生成する部品。掲示板のことを知らない |
| 機能の部品 | `src/modules/<feature>/presentation/` | 掲示板を知っている部品と Server Action |
| 画面 | `src/app/**/layout.tsx`、`page.tsx` | `@/di/*` でデータを取り、機能の部品を並べる |

### Server Component と Client Component

- 既定は Server Component。データは `layout.tsx` / `page.tsx` で取り、props で渡す。
- `"use client"` は、クリック・入力中の状態・ブラウザの機能（Cookie の書き込み、`usePathname`）が必要な末端の部品にだけ付ける。

### 状態の見せ方

| 状態 | 見せ方 |
| -- | -- |
| 未ログイン | `/sign-in` へリダイレクトする（`proxy.ts` とページの両方で確認） |
| 存在しない・所属していない・ID の形式が不正 | 404 画面（区別しない） |
| 入力エラー（use case が `{ ok: false, reason }` を返す） | フォームの該当項目の近くにメッセージを表示し、入力値は残す |
| 操作の回数が上限を超えた（`rate_limited`。要件 34.3） | 入力エラーと同じ場所に「操作の回数が多すぎます。しばらく待ってから、もう一度お試しください。」と表示する |
| 送信中 | 送信ボタンを無効にし、文言を「〜中…」にする |
| 一覧が空 | 空であることと、次にできる操作を1行で示す |
| 取り消せない操作の確認 | `ui/alert-dialog` で確認する。見出しで何をするかを問い、説明で取り消せない影響を書く。ボタンは「キャンセル」と「〜する」 |
| 確認ダイアログの中の操作の失敗 | ダイアログを閉じずに、ボタンの上に `role="alert"` の赤い文字（`text-destructive text-sm`）で表示する。フォームの入力エラーと同じ見た目にする |

### 配置の考え方

1. よく使う操作ほど、近くて目立つ場所に置く（掲示物の登録・撤去タスクは掲示板のヘッダー）。
2. 目的ごとにまとめる。サイドバーは「どの掲示板を見るか」、ヘッダーは「その掲示板で何をするか」、アカウントメニューは「自分に関すること」。
3. 取り消せない操作ほど遠くに置き、確認を挟む（掲示板の削除は設定画面の奥で確認ダイアログ）。やり直せる操作（ログアウト）に確認は付けない。
4. 独自の配置にする理由がなければ、利用者が他のサービスで見慣れた形に合わせる。
5. スマホで押せる部分は 44px 以上にする。

### 画面幅

- `md`（768px）以上：サイドバーを常に表示する。
- `md` 未満：サイドバーを折りたたみ、上部バーのメニューボタンで開く。

| 領域 | 内容 | データ |
| -- | -- | -- |
| 上部 | アプリ名 `tackup` | 固定 |
| 掲示板一覧 | 所属する掲示板を、所属した日時の新しい順に並べる | `listMyBoards(userId)` |

- 所属する掲示板がない：一覧の位置に「所属する掲示板はありません」と表示する。
- 掲示板名が長い：1行に収まらない分は省略記号で切り、全体は `title` 属性で確認できるようにする。

## S5 掲示板作成 `/boards/new`

要件 21（掲示板管理）、22（公開設定）。

```
┌───────────────────────────────────────────┐
│ 掲示板を作成                               │
│                                           │
│ 掲示板名 *                                 │
│ ┌───────────────────────────────────────┐ │
│ │                                       │ │
│ └───────────────────────────────────────┘ │
│ 50文字以内                                 │
│                                           │
│ 公開設定                                   │
│ ◉ 非公開  メンバーだけが閲覧できます         │
│ ○ 公開    招待リンクと QR コードから        │
│           ログインなしで閲覧できます         │
│                                           │
│                          [ 作成する ]      │
└───────────────────────────────────────────┘
```

### 入力項目

| 項目 | 部品 | ルール | 初期値 |
| -- | -- | -- | -- |
| 掲示板名 | `ui/input` + `ui/label` | 必須。前後の空白を除いて1〜50文字（`parseBoardName`）。`maxLength` も 50 | 空 |
| 公開設定 | `ui/radio-group` | 非公開 / 公開 のどちらか。それぞれに意味の説明を付ける | 非公開 |

### 操作

| 操作 | 処理 |
| -- | -- |
| 「作成する」 | Server Action `createBoardAction` → `createBoard({ name, isPublic, userId })`。`userId` はフォームではなくセッションから取る |
| 成功 | `/boards/{boardId}` へリダイレクト |
| `name_empty`・`name_too_long` | Server Action で理由に応じた文言に変え、掲示板名の下に表示する。入力値は残す |
| 想定外のエラー（DB に接続できないなど） | Server Action では捕まえずに投げ直し、`/boards` のエラー画面（`src/app/boards/error.tsx`）に「問題が発生しました」と「もう一度試す」ボタンを表示する。サイドバーは残る |
| 成功後のサイドバー | 作った掲示板がすぐ一覧に出る（`revalidatePath("/boards", "layout")`） |
| 送信中 | ボタンを無効にし「作成中…」 |

見出しの下の説明文と、入力欄の例（placeholder）は表示しない（見出しと項目名で十分伝わるため）。

ブラウザ標準の入力チェック（`required` による吹き出し）は `noValidate` で止め、エラーはサーバーが理由に応じて決めた文言だけを掲示板名の下に表示する。`required` は必須項目であることを支援技術に伝えるために残す。

### 部品構成

```
src/app/boards/new/page.tsx                  [Server] 見出しと CreateBoardForm を並べる
└ CreateBoardForm                            [Client] modules/board/presentation
   └ createBoardAction                       [Server Action] modules/board/presentation/actions.ts
```

## S2 掲示板ボード（メンバー向け）`/boards/{boardId}`

要件 12・12.1。設計は `docs/design/board-view.md`。ヘッダーの各導線は、対応するステップで追加する。

```
┌───────────────────────────────────────────┐
│ 中野のボード   [非公開]      [＋ 掲示物を登録] │
│                                           │
│ ┌──────┐ ┌──────┐ ┌──────┐                │
│ │      │ │      │ │      │                │
│ │      │ └──────┘ │      │                │
│ └──────┘ 夏祭り   │      │                │
│ お知らせ ┌──────┐ └──────┘                │
│         │      │ 清掃の案内               │
│                                           │
│              [続きを見る]                  │
└───────────────────────────────────────────┘
```

### 表示する情報

| 領域 | 内容 | データ |
| -- | -- | -- |
| ヘッダー | 掲示板名（`h1`）と、公開 / 非公開のバッジ（`ui/badge`。公開は地球、非公開は鍵のアイコン付き） | `getBoard({ boardId, userId })` |
| 本文 | 公開中の掲示物（`PostBoard`）。1 件もなければ「まだ掲示物はありません」 | `listBoardPosts({ boardId, userId, cursor })` |

### 掲示物の一覧（`PostBoard`）

メンバー向けと一般閲覧者向け（`/b/{inviteToken}`）で同じ部品を使う。管理用の導線は置かない。

| 項目 | 内容 |
| -- | -- |
| 表示する掲示物 | 公開中のものだけ（要件 10）。掲示開始前・期限切れ・撤去済み・下書きは、メンバーにも表示しない |
| 並び順 | 掲示開始の新しい順 |
| レイアウト | masonry。CSS の段組みで、幅に応じて 2〜4 段。タイルの途中で段が切れないようにする |
| タイル | サムネイルとタイトル。サムネイルには幅と高さを付け、読み込む前に縦横比が決まるようにする |
| 掲示物詳細への導線 | ステップ6で足す。それまではタイルをリンクにしない |
| ページ分け | 1 ページ 50 件。続きがあれば「続きを見る」を出し、`?after={続きの位置}` で次のページを開く。`after` の形が合わなければ最初のページを出す。形は正しいがその先に掲示物がないとき（前のページを開いたあとに掲示期間が終わったなど）は、最初のページへ移動する |
| サムネイルの URL | 表示のたびに発行する署名付きの URL（5 分で切れる）。あとからスクロールしたときに読み込むと期限が切れているので、遅延読み込みにせず、表示のときにすべて読み込む |

### ヘッダーの導線（追加する時期）

| 導線 | 表示条件 | 追加するステップ |
| -- | -- | -- |
| 掲示物登録・撤去タスク・台帳 | メンバー | 4・7・8 |
| 招待リンクの表示・コピー | 公開掲示板 | 9 |
| 招待リンクの再発行・掲示板設定・メンバー管理 | admin | 9 |

ステップ1では、まだ遷移先がない導線は表示しない。

### 招待リンク（公開掲示板のみ）

要件 20、38.10。

| 項目 | 内容 |
| -- | -- |
| 表示条件 | 公開掲示板のときだけ表示する（admin・poster とも）。非公開の掲示板では何も表示しない |
| 表示内容 | 招待リンクの絶対 URL（`{BETTER_AUTH_URL}/b/{token}`）と「コピー」ボタン |
| データ | `getBoard` の `inviteUrl`（非公開なら `null`）と `role` |
| コピー | クリップボードにコピーし、ボタンの文言を少しの間「コピーしました」に変える。コピーできなかったときは URL を選択状態にして、手でコピーできるようにする |
| 再発行（admin のみ） | 「再発行」ボタン → 確認ダイアログ（「今のリンクは使えなくなります」）→ 確定で新しいリンクを発行し、表示中の URL を差し替える。poster には表示しない |
| 送信中 | 再発行の確定ボタンを無効にし「再発行中…」 |
| エラー | 想定外のエラーは `error.tsx` に任せる。`forbidden`・`board_not_found`（画面を開いたあとにロールや所属が変わった場合）と `board_not_public`（画面を開いたあとに非公開に変わった場合）は「再発行できませんでした。」と表示する |
| 不整合 | 公開掲示板に有効な招待リンクがない状態は起きないはずなので、想定外のエラーとして扱う |

### 最後に開いた掲示板の記録

- 画面が表示されたら、Cookie `last-board-id` にこの掲示板の ID を保存する。
- 属性：`path=/`、`max-age` 1年、`SameSite=Lax`。
- ブラウザで書き込む（Server Component では Cookie を書けないため）。サイドバーのリンクの先読みでは記録されない。
- 書き込みには Cookie Store API（`cookieStore.set`）を使う。安全な接続（HTTPS か `localhost`）でしか使えないので、開発中にスマホから `http://192.168...` で開いたときは記録しない。

### 状態

| 状態 | 見せ方 |
| -- | -- |
| `getBoard` が `board_not_found`・`forbidden` | 404 画面（掲示板の存在を知られないよう区別しない） |

### 部品構成

```
src/app/boards/[boardId]/page.tsx            [Server] getBoard。失敗なら 404
├ BoardHeader                                [Server] modules/board/presentation
│ └ InviteLinkSection（公開掲示板のみ）         [Client] コピー・再発行（Server Action reissueInviteTokenAction）
└ RememberLastBoard                          [Client] modules/board/presentation（Cookie を書く。何も表示しない）
```

## S4 掲示物登録 `/boards/{boardId}/posts/new`

要件 7・8・9・10、38.1。設計は `docs/design/post-registration.md`。掲示板ボードのヘッダーの「掲示物を登録」から開く（admin・poster とも）。

```
┌─────────────────────────────────┐
│ 掲示物を登録                      │
│                                  │
│ ファイル *                         │
│ [ファイルを選択]                   │
│ PDF・JPEG・PNG・WebP（20MB まで）  │
│ ┌──────────┐                     │
│ │ サムネイル │                     │
│ └──────────┘                     │
│                                  │
│ タイトル *                        │
│ [夏祭りのお知らせ             ]    │
│ 100文字以内                       │
│                                  │
│ 掲示開始 *        掲示終了 *       │
│ [2026/10/01 09:00] [          ]   │
│                   ☐ 無期限にする   │
│                                  │
│                      [登録する]   │
└─────────────────────────────────┘
```

### 入力項目

| 項目 | 部品 | 内容 | 初期値 |
| -- | -- | -- | -- |
| ファイル | `ui/input`（`type="file"`） | 掲示物の原本。PDF・JPEG・PNG・WebP、20MB まで。選ぶとすぐにサムネイルを作って表示する | なし |
| タイトル | `ui/input` | 必須、100文字以内。前後の空白は取り除く | ファイルを選んだとき、空ならファイル名（拡張子を除く） |
| 掲示開始 | `ui/input`（`type="datetime-local"`） | 必須 | 画面を開いた日時 |
| 掲示終了 | `ui/input`（`type="datetime-local"`） | 無期限にしないときは必須。掲示開始より後 | なし |
| 無期限にする | `ui/checkbox` | チェックすると、掲示終了の入力欄を無効にし、掲示終了を未設定（無期限）で登録する。外すと、入れてあった掲示終了に戻る | チェックなし |

画面では、原本を「ファイル」と呼ぶ（利用者が選ぶものの呼び名に合わせる）。仕様書とコードでは、サムネイルと区別するために「原本」と呼ぶ。

日時は端末のタイムゾーンで入力し、ブラウザが ISO 8601（UTC）に変えて送る。過去の日時も登録できる（すでに貼り出した掲示物を、あとから記録できるようにするため）。

### サムネイル

- PDF は pdf.js で 1 ページ目を描画する。画像は原本を縮小する。
- 長辺を 800px にし、WebP（品質 0.8）で作る。WebP に書き出せないブラウザでは `canvas.toBlob` が PNG を返すので、返ってきた種類を確かめ、WebP でなければ白い背景に重ねて JPEG（品質 0.8）で作り直す。作った種類は結果の `contentType` で返す。
- 作ったサムネイルの幅と高さも返す（ステップ5の masonry で縦横比に使う）。

### 登録の流れ

「登録する」を押すと、次の順に進める。途中で失敗したら、そこで止めてボタンの上に文言を出す。

1. `createUploadUrlsAction` で、原本とサムネイルのアップロード URL を発行する
2. ブラウザから、原本とサムネイルを署名付きの URL へ直接 PUT する
3. `registerPostAction` で掲示物を登録する（`published` で登録する）
4. 掲示板ボード（`/boards/{boardId}`）へ移動する

### 状態

| 状態 | 見せ方 |
| -- | -- |
| 形式・サイズが許可されていない（`parseOriginalFile` の `reason`） | ファイルの入力欄の下に理由に応じた文言を出す |
| サムネイルの作成中 | ファイルの入力欄と「登録する」を無効にし、「サムネイルを作成中…」を出す |
| PDF・画像として読めない（`pdf_unreadable`・`image_unreadable`） | ファイルの入力欄の下に文言を出す |
| ファイルを選んでいない・日時が入っていない | 送らずに、ボタンの上に文言を出す |
| 登録中 | ファイルの入力欄と「登録する」を無効にし、ボタンの文言を「登録中…」にする |
| アップロードできない（通信できない・ストレージに拒否された） | 「アップロードできませんでした。通信の状態を確かめて、もう一度お試しください。」 |
| タイトル・掲示期間が決まりに合わない | 理由に応じた文言を出す |
| ファイルを確認できない（`file_invalid`。中身が申告した形式と違う、確認のあとに差し替えられた、など） | 「ファイルを確認できませんでした。ファイルを選び直して、もう一度お試しください。」 |
| 上限に達している（`post_limit_exceeded`・`storage_limit_exceeded`） | 理由に応じた文言を出す |
| 所属していない（`board_not_found`・`forbidden`。画面を開いたあとに所属が変わった場合） | 「この掲示板に掲示物を登録できません。」 |
| 想定外の失敗（worker を読み込めない、DB・ストレージの障害など） | `error.tsx` の汎用のエラー画面を出す |

## 決めたこと（要件に追記していない仕様）

- ログアウトはサイドバー下部のアカウントメニューの中に置き、確認ダイアログは出さない。
- アイコンは Google の画像を使い、画像がない場合（将来メールアドレスとパスワードの認証を加えた場合を含む）は名前の頭文字を表示する。
- 最後に開いた掲示板の Cookie は `last-board-id`（1年）。
- 公開設定はラジオボタンで選び、それぞれの意味を説明する（切り替えスイッチでは「公開」の意味が伝わりにくいため）。
- まだ遷移先のない導線は、無効表示ではなく非表示にする。
