# Design doc: 掲示物詳細・QR コード（ステップ6）

掲示物詳細（`/posts/{publicId}`）を、見てよいかの判定を 1 つの関数にまとめて作る。公開掲示板の公開中の掲示物は誰でも、それ以外はその掲示板のメンバーだけが見られる。
QR コードは、この URL を SVG にしてサーバーで作る。閲覧の記録（`ViewLog`）は、応答を返したあとに書く。
PR は 4 つに分ける（説明文と外部リンク → 掲示物詳細 → 閲覧の記録 → QR コード）。

根拠: [requirements.md](../requirements.md) の 13・14・22・24・30・33・34.3・34.6・37.6・38.3・38.11。

## 見てよいかの判定

| 見る人 | 公開掲示板・公開中 | 公開掲示板・公開中でない | 非公開の掲示板 |
| -- | -- | -- | -- |
| その掲示板のメンバー | 見られる | 見られる | 見られる |
| ログイン中で、メンバーでない | 見られる | 404 | 404 |
| ログインしていない | 見られる | 404 | サインイン画面へ移動し、ログイン後に元の URL へ戻る |

「公開中でない」は、掲示開始前・期限切れ・撤去済み・下書き。存在しない `publicId` は、誰が開いても 404。

## 決めたこと

| 項目 | 決めたこと | 理由 |
| -- | -- | -- |
| 判定の置き場所 | domain の 1 つの関数（`decidePostAccess`）。結果は「見られる・ログインが要る・見つからない」の 3 つ | 要件 22 の「閲覧可否の判定は共通化する」。ページ・QR コード・閲覧の記録が同じ判定を使う |
| メンバーが公開中でない掲示物を見ること | 見られる。画面に状態（掲示開始前・掲示期間は終了、など）を出す | 貼ってある期限切れの掲示物の QR コードを読んだメンバーが、内容を確かめられる。台帳（ステップ8）からも同じページを使う |
| 原本の見せ方 | 画像は原本をそのまま表示する。PDF はサムネイルを表示し、「PDF を開く」で別のタブに開く | PDF を画面に埋め込むには、CSP でストレージからの埋め込みを許す必要がある。ブラウザの PDF 表示に任せる |
| 保存 | 原本の署名付き URL に、ダウンロードさせる指定とファイル名を付ける | サーバーを経由せずに保存できる（要件 34） |
| 共有 | ブラウザの共有の機能を使い、使えないブラウザでは URL をコピーする | 追加の仕組みが要らない |
| 外部リンク | `http`・`https` の URL だけを受け付ける。開くときは別のタブで、開き元の情報を渡さない | `javascript:` などの URL を登録されると、押した人のブラウザでスクリプトが動く |
| ログイン後に元の URL へ戻る | サインイン画面に戻り先を渡す。受け付けるのは、このアプリの中のパスだけ | 外部の URL を渡されると、ログイン直後に別のサイトへ飛ばされる |
| 閲覧の記録 | `after` で応答のあとに書く。失敗しても表示に影響させない。メンバーの閲覧も、公開中でない掲示物の閲覧も記録する | 要件 24・34.6。だれの閲覧かは持たないので、区別しない |
| QR コード | `qrcode` で SVG を作り、Route Handler（`/posts/{publicId}/qr`）で返す。メンバーだけが取得でき、撤去済みと下書きには出さない | SVG は印刷しても粗くならない。ページに `<img>` で置けるので、HTML に SVG を埋め込まずに済む |
| QR コードを出す時期 | 掲示開始前でも出す | 要件 14 は「公開中の掲示物」だが、貼り出す前に印刷できないと使えない。要件を書き換える |
| 掲示板ボードからの導線 | タイルを掲示物詳細へのリンクにする。先読みはしない | 先読みのたびに署名付き URL を発行し、閲覧の記録が増える |
| 回数の制限 | `/posts/…` を、招待リンクと同じ IP アドレスごとの制限に入れる | 要件 34.3 |

## 検討した代替案

| 案 | 却下理由 |
| -- | -- |
| メンバーにも、公開中の掲示物だけを見せる | 期限切れの掲示物を確かめる手段が、台帳ができるまでなくなる |
| PDF を `<iframe>` で埋め込む | CSP の `frame-src` にストレージを足す必要がある。スマートフォンのブラウザは、埋め込みの PDF を表示できないものが多い |
| 原本をサーバー経由で配信する | サーバーの転送量が増える（要件 34 で避けるとしている構成） |
| QR コードをブラウザで作る | Client Component とライブラリの読み込みが増える。印刷用に保存するには、結局ファイルにする必要がある |
| 閲覧の記録を、表示と同じ処理の中で書く | 記録の失敗や遅れが、表示に影響する（要件 24） |

## PR の分け方

| # | 内容 | 主な確認 |
| -- | -- | -- |
| 1 | 説明文と外部リンクの決まり、登録のフォームへの追加 | ユニットテスト、e2e |
| 2 | 判定、`getPostDetail`、掲示物詳細の画面、掲示板ボードからの導線、ログイン後に戻る、回数の制限 | ユニットテスト、e2e（公開・非公開・公開中でない） |
| 3 | `ViewLog` のテーブルと記録 | ユニットテスト、`*.db.test.ts`、e2e |
| 4 | QR コード | ユニットテスト、e2e |

## やらないこと

- 掲示物の編集・撤去（ステップ7・8）
- 閲覧数の表示・集計（要件 31）
- `ViewLog` の保持期間を過ぎた記録の削除。運用の仕組み（要件 34.8）と一緒に決める
- 署名付き URL のキャッシュ
