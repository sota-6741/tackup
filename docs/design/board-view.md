# Design doc: 掲示板ボードの表示（ステップ5）

公開中の掲示物を取り出す条件を Repository の 1 か所に置き、メンバー向け（`/boards/{boardId}`）と一般閲覧者向け（`/b/{inviteToken}`）の両方が、同じ use case で一覧を作る。
2 つの経路の違いは「その掲示板を見てよいか」の確かめ方だけにする。
PR は 4 つに分ける（判定と一覧の取得 → メンバー向けの表示 → 招待リンクからの表示 → 公開の経路の回数の制限）。

根拠: [requirements.md](../requirements.md) の 10・11・12・20・22・32・33・34・34.3・34.5・37.5・38.2。画面は [screens.md](../screens.md) の S2。

## 構成

```text
/boards/{boardId}（メンバー）          /b/{inviteToken}（一般閲覧者）
        │                                      │
 getBoard（所属を確認）              getPublicBoard（有効な招待リンク かつ 公開掲示板）
        └──────────────┬───────────────────────┘
                       ▼
       listPublishedPosts({ boardId, cursor })
        1. PostRepository.findPublished（公開中の条件・並び順・続きの取得）
        2. サムネイルの署名付き URL を並行に発行
                       ▼
                 PostBoard（masonry）
```

`listPublishedPosts` は掲示板を見てよいかを確かめない。呼び出す側の use case が確かめたあとで呼ぶ。画面からは直接呼ばせない（`src/di` から出さない）。

## 決めたこと

| 項目 | 決めたこと | 理由 |
| -- | -- | -- |
| 公開中の条件 | SQL の条件を Repository の中の 1 つの関数にし、domain の `isPublished` と同じ決まりであることを、同じ例のテストで確かめる | 条件を画面や use case に書かせない（要件 32）。無期限（`expiresAt` が `null`）の扱いを 1 か所に閉じ込める |
| 並び順 | 掲示開始の新しい順、同じ日時なら ID の大きい順 | 新しく貼り出されたものが上に来る。ID を足して順序を一意にしないと、続きの取得で抜けや重複が出る |
| 続きの取得 | 並び順のキー（掲示開始と ID）を 1 つの文字列にして渡す。1 ページ 50 件 | 要件 34.5。`OFFSET` を使わない |
| 画面に渡す形 | `publicId`・タイトル・サムネイルの URL と幅・高さだけ | 内部の ID とストレージのキーを画面に出さない |
| サムネイルの URL | 表示のたびに、署名付きの URL を並行に発行する。URL のキャッシュは入れない | 要件 34 の「必要と分かってから入れる」。ローカルのエミュレーターでは IAM の通信が起きないので、今は測れない |
| masonry | CSS の段組み（`columns`）で組む。各タイルに幅と高さから縦横比を指定する | ライブラリも JavaScript も要らない。画像が読み込まれる前に高さが決まるので、表示が動かない |
| 掲示物詳細へのリンク | 付けない | 遷移先（`/posts/{publicId}`）はステップ6で作る。遷移先のない導線は出さない（screens.md） |
| 招待リンクの失敗の見せ方 | 存在しない・失効した・非公開の掲示板を、すべて同じ 404 にする | 要件 22。掲示板があるかどうかを知らせない |
| 公開の経路の回数の制限 | IP アドレスごとに 1 分 120 回。`proxy.ts` で数え、超えたら 429 を返す | ページの中からは HTTP ステータスを 429 にできない。IP の取り方は PR 4 で決める |

## 検討した代替案

| 案 | 却下理由 |
| -- | -- |
| 全件を取ってから `isPublished` で絞る | 掲示物が増えるほど遅くなる。続きの取得もできない |
| 並び順を登録の新しい順（`createdAt`）にする | 掲示開始を先の日時にして登録した掲示物が、公開された時点で下のほうに出る |
| masonry のライブラリを使う | 段の高さをそろえる必要が出るまでは、CSS の段組みで足りる |
| 無限スクロール | Client Component と Server Action が要る。50 件を超える掲示板は少ないので、「続きを見る」のリンクで足りる |
| メンバー向けと一般閲覧者向けで別々の一覧の use case を作る | 公開中の条件と URL の発行が二重になる（要件 22 の「画面ごとに再実装しない」） |

## PR の分け方

| 1 | domain の `isPublished`・`isExpired`、続きの取得のキー、`PostRepository.findPublished`、索引 | ユニットテスト、`*.db.test.ts`（無期限・掲示開始前・期限切れ・撤去済み・下書き） |

## やらないこと

- 掲示物詳細とそこへのリンク、QR コード、`ViewLog`（ステップ6）
- 期限切れの一覧（撤去タスク。ステップ7）。期限切れの SQL の条件は、そのときに公開中の条件と同じ場所へ足す
- 署名付き URL のキャッシュと、オブジェクトの `Cache-Control`（実測してから）
- 掲示板ボードでの絞り込み・検索
